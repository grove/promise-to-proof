# Portable compatibility replay

The root README.md, commands.json and original logs describe the historical experiment. They are unchanged. portable-results/ contains a second executed experiment in a fresh directory, with its own exact commands, versions, fixture metadata, actual CLI observations and return codes.

portable-replay.py requires neither the historical /private/tmp location nor the original scratch layout. Keep the evidence directory together, provide the repository containing the real controller and existing fixture helper, and provide the two verified release locations. The new output directory must not exist. All npm dependencies and cache writes go into that output directory. npm ci uses the retained lockfile and --ignore-scripts. The replay checks Node 26.9.0 and npm 11.19.1 and validates the FizzBee and MBT binary hashes before running.

```sh
python3 /path/to/evidence/portable-replay.py \
  --repo /path/to/promise-to-proof \
  --fizz /path/to/fizzbee-v0.5.3-macos_arm/fizz \
  --mbt /path/to/fizzbee-mbt-0.2.0-macos_arm \
  --output-dir /path/to/new-replay-directory
```

The replay constructs a new Git fixture using checks/test_p2p_delivery.py's repo helper. It never uses the helper module's fake transport. The portable adapter reads P2P_CONTROLLER, which the script sets to the explicitly supplied repository's public CLI path. It observes real status output for the unstarted acceptance item. The script starts and stops MBT's localhost server, so port 50051 must be available. Network access is needed for locked npm packages on a cold cache; sockets may need scoped sandbox approval. No agent stage is dispatched.

Observed new run: good exit 0; deliberately wrong observation exit 1; seed-42 replay exit 1. All three invoke the actual controller status CLI and log BLOCKED with no delivery invocation exists. The two failures show expected BLOCKED versus actual STATUS_WRONG. This remains a narrow transport compatibility result, not controller lifecycle conformance or issue acceptance.

The complete generated model graph remains in portable-fresh/controller-graph in scratch. portable-results/artifact-hashes.json retains its hashes. The tiny graph can be regenerated by the portable script; dependencies, binaries and graph directories are omitted from this evidence bundle.
